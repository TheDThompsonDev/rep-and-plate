# B1-demo-removal — findings F1, F3, C6, dead demo data (section 1 "Completeness gaps")

## Plan (written before editing)

Goal: the shipped web app contains no prototype scaffolding: no Today dashboard, no demo captures, no scripted sample replies, no hard-coded card copy, no dead welcome/demo conversation.
Done when: (1) `#today` lands on Chat with no "LOCAL DEMO" badge or fabricated steps/sleep anywhere; (2) the capture modal and chat menu offer no demo meals; (3) a typed meal with connected chat unavailable gets the existing honest guidance and stores nothing; (4) non-AI meal cards show the meal's own title and note; (5) `initialState().messages` is empty and `referenceConversation` is gone; (6) tsc, vitest, mobile check, and the focused Playwright specs pass.
Approach: pure removal (repair). The honest no-AI reply already exists at the end of `submitText` ("I can't answer freely while connected chat is unavailable … Use Nutrition → Enter meal manually"); demo branches simply stop intercepting text before it.
Context: ledger NUTRITION entries (lines 155-157, 172-180) record that fresh state must stay empty, that `isExampleMeal`/`personalMeals` exist because *persisted* accounts can contain example meals interleaved with real ones, and that tests demonstrating samples use `demoState()` (docs/context/nutrition.md:19-25). `upgradeChat` convention: never rewrite old conversations. No failed approaches recorded for Today/demo removal.
Change:
- `src/domain.ts` → drop `"Today"` from `Page`; drop `pendingMeal` from `stateSchema`; `initialState().messages = []`; remove `referenceConversation`/`referenceDinner` (dinner fixture inlined into `demoState`, id kept for tests); remove `demoMeals`/`makeMeal`; `interpretText` keeps only the bench parser; `resolveReview` protein branch inlines its example meal.
- `src/App.tsx` → remove Today nav entry/render, `insights`, `showInsight`, Info modal, legacy sidebar/topbar/bottom-nav, `addDemoMeal`, capture-modal demo buttons, `pendingMeal` cups parser, `meal`/`repeat` interpretation branches, `onSample`; `#today` → Chat (hash normalized to `#chat`); shell classes `chat-home`/`chat-main` unconditional.
- `src/ChatLayer.tsx` → meal card shows `meal.title`, `meal.note`; remove "Dinner added" and chicken/broccoli copy; remove demo alt text; remove "Try a sample capture" menu entry and `onSample` prop; sample-flow copy in menu/about.
- `src/chat.css`, `src/styles.css` → remove rules whose every selector names a class that no longer appears in any `.tsx` (script-assisted, reviewed by hand).
- Tests: `tests/no-demo.spec.ts` (new), `tests/flows.spec.ts` (two demo tests), `src/domain.test.ts`, `src/day.test.ts`.
Keep consistent: `mobile/src/ChatScreen.tsx:370` filters `welcome` (no-op once fresh state has no welcome; untouched); `src/features/cloud/sync.ts:94` treats "no non-welcome messages" as fresh (still true for `[]`); `demoState()` consumers in `tests/flows.spec.ts`, `tests/nutrition-connected.spec.ts`, `tests/onboarding.spec.ts`, `src/*.test.ts`, `src/platform/browser-records.test.ts` use `.meals` only; `resolveReview` sample reviews (`protein`/`fries`) only exist in `demoState` but persisted accounts may hold them, so the branches stay.
Test: `npx vitest run src/domain.test.ts src/day.test.ts` (red on interpretText/welcome expectations); `npx playwright test tests/no-demo.spec.ts` (red: Today renders, demo buttons present, sample meal stored).
Open: welcome filter in `ChatLayer` — keep (persisted records from every earlier release contain the `welcome` message; `upgradeChat` must not rewrite conversations). `isExampleMeal`/`personalMeals` — keep for the same persisted-data reason and for `demoState()` fixtures.

## Change and mechanism

- **F1 Today dashboard** (`src/App.tsx`): the `navigation` array (seven entries with icons) is now `pages`, a plain hash→page list without `"Today"`; both hash lookups (`useState` initializer and the `hashchange` effect) fall through to `"Chat"` for unknown hashes, so `#today` lands on Chat with no special case. The mount effect additionally does `history.replaceState(null, "", "#chat")` when the hash is `#today`, so old bookmarks normalize (`navigate()` already writes `#chat` for Chat). Deleted: the `insights` array, `showInsight`, the `info` modal state and its `<Modal>`, the whole `page === "Today"` render (253 lines: "LOCAL DEMO", fabricated steps/sleep, "Sample history · 14 days"), `startChat`, `startWorkout`, `totals`/`todayMeals`/`dateLabel`/`pending`, and the `<aside className="sidebar">`, `<header className="topbar">` and `<nav className="bottom-nav">` shells that `chat.css:11-15` already hid on every non-Today page. `app-shell chat-home` and `main-content chat-main` are now unconditional. `Page` in `src/domain.ts:174` no longer includes `"Today"`.
- **F3 demo captures**: `addDemoMeal`, the "OR EXPLORE A DEMO" block in the capture modal, the `pendingMeal` cups parser and the `meal`/`repeat` branches of `submitText` are gone; `pendingMeal` is removed from `stateSchema` (zod strips the key from older snapshots; the only consumer was the cups parser). `interpretText` returns `workout | unknown` only; the bench parser is intact because it feeds `startPlan`/`recordSet`. With connected chat unavailable, a typed meal now reaches the existing fallback reply ("I can't answer freely while connected chat is unavailable… Use Nutrition → Enter meal manually…") and nothing is stored; with chat available the text goes to `sendAI` exactly as before (demo phrases were already routed to AI when available). `demoMeals`/`makeMeal` are deleted; the `protein` review branch of `resolveReview` inlines its example meal (`example: true`, same numbers) because persisted accounts may still hold unresolved sample reviews. ChatLayer's "Try a sample capture" menu item and the `onSample` prop are removed (the item would otherwise open an empty picker), and two copy strings stop promising "sample flows".
- **C6 card copy** (`src/ChatLayer.tsx` meal card): title is `meal.title`; description is "Sample capture" for examples, otherwise `${category} · estimated portions` / "Saved to your day" by `meal.confidence`; the confidence footer renders `meal.note` whenever present (previously only Dinner, with hard-coded chicken/broccoli text for non-AI sources). The `demo-dinner-photo` alt-text branch is gone.
- **Dead data** (`src/domain.ts`): `initialState().messages` is `[]`; `referenceConversation()` and `referenceDinner()` are deleted. `demoState()` stays as the documented test fixture (its dinner meal is inlined with the same `chat-demo-dinner` id; `messages: []`). The `welcome` filter in `ChatLayer` (and native) **stays**: every account saved by an earlier release carries that message and `upgradeChat` must not rewrite conversations (documented convention, tested in `domain.test.ts` "chat upgrade").
- **`isExampleMeal`/`personalMeals` stay**: nothing in the app creates example meals any more, but persisted accounts contain them (interleaved with real edits per docs/context/nutrition.md:19), `demoState()` fixtures rely on them, and `resolveReview` still flags sample-review meals.
- **CSS**: `scratchpad/prune-css.mjs` took the class names from lines removed in `src/App.tsx`/`src/ChatLayer.tsx`, kept any still referenced in `src/**/*.ts(x)` or `index.html`, and deleted a rule only when every selector in its list named a dead class, pruning emptied `@media` blocks. `src/styles.css` 3658 → 2527 lines (251 rules: sidebar/topbar/bottom-nav shell, Today grids, insight cards, metric cards, workout hero, capture strip, demo-capture, modal-divider, demo-label); `src/chat.css` lost only the `.chat-home > .sidebar, … > .topbar { display: none }` rule. PostCSS parses both files; braces balanced; CRLF preserved. Pre-existing dead classes (`insights-grid`, `sample-phrases`) were deliberately left alone.
