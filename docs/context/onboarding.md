# Onboarding and first tracking action (working; awaiting acceptance)

Current implementation/evidence: [October 2 polish](../audits/2026-10-02-onboarding-polish/report.md). This extends the prior goals/weight and nutrition setup without changing estimator formulas or account record ownership.

`useOnboarding` owns flow state and the validated setup draft shared by web/native renderers. `draft.ts` bounds and strictly parses device-only data; keys separate guest and user UUID. Account resume beyond confirmation additionally uses the existing project/account ownership verifier. Draft data excludes email/password/auth tokens and ownership confirmation. Draft changes do not apply health records; final confirmation saves goals/body details and only explicitly approved targets. Stable measurement IDs keep completion retries from creating duplicate entries.

Async draft writes are serialized. Completion waits for queued writes, checks the session epoch, writes its legacy-compatible completion marker, clears the corresponding draft and checks the session again. A completed marker wins over stale drafts. Replay does not overwrite drafts. In-app guest sign-in must preserve the already entered account dialog; do not reset `entered` on the first null-to-user transition. Account changes/sign-out clear transient fields. Confirmed deletion cleanup removes only the deleted user UUID's draft, including when another account owns the active records.

Nutrition form snapshots retain whether review is estimated/manual and every edited target value. Returning through goals invalidates pending target review so a changed weight requires another estimate/review. Profile target editing keeps its direct alternatives; onboarding's manual/details-only alternatives are expandable.

New completion markers optionally set `firstLogPending`. Existing markers without it behave as before. `hasFirstLog` requires a real personal meal, timed activity or completed recorded workout. Examples, purchases and body setup are insufficient. The first prompt opens existing manual forms without saving fictional entries and survives cancellation/reload until real tracking or explicit deferral. Web embeds it inside the Chat scroll surface so fixed navigation remains immediate.

Guards: draft/first-log unit tests; web/native onboarding-nutrition, onboarding-resume, onboarding-first-log and account-security journeys. Full final checks are retained in the linked report's evidence folder. Human first-use observation and physical-device testing remain separate from functional verification.

First-log action callbacks stay stable across renders: a rejected completion-marker write must not automatically retry on unrelated navigation, while the actual meal/activity remains saved. Missing Spot artwork must preserve text/control layout; intrinsic image dimensions use responsive height and zero-minimum grid tracks. Regressions cover both adverse paths.

The goals step also collects an optional training week (days per week 2–6, available equipment, experience) through the same `FitnessSetupDraft`. `applyFitnessSetup` derives `profile.trainingProgram` deterministically in `src/features/progress/training-program.ts` from the starter plans in `src/workout-plans.ts`, substituting bodyweight or chosen-equipment movements and using two sets for someone new; loads are never stored and nothing auto-progresses. An empty training-days answer leaves any existing week untouched, so the You editor, native profile and onboarding skip all preserve it; removal is an explicit action on Workouts. Draft fields have zod defaults so drafts saved before the week parse. Web and native Workouts lead with "Your week" and the next session (counted from finished sessions carrying a program title since the week began), with starter plans and the AI builder beneath; the AI request carries only the answers (`context.trainingProgram`). `training-week.ts` holds the helpers that depend on `workouts.ts`, keeping the schema module free of the `domain.ts` import cycle. Guards: `training-program.test.ts`, `fitness-goal.test.ts`, `tests/training-program.spec.ts`, `tests/fitness-setup.spec.ts`, `tests/workout-surface.spec.ts`, `mobile/e2e/fitness-setup.spec.ts`.
